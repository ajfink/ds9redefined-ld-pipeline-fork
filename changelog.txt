====================================

Version history
---------------

Version 1 (retrospective summary; reconstructed 2026-11-14)

Version 2 (retrospective summary; reconstructed 2026-11-14)
FROM Version 1 -> Version 2

Version 3 (retrospective summary; reconstructed 2026-11-14)

Version 4 (retrospective summary; reconstructed 2026-11-14)
FROM Version 3 -> Version 4

Version 5 (retrospective summary; reconstructed 2026-11-14)
FROM Version 4 -> Version 5
- Added explicit audio timing diagnostics, robust DVD-picture/audio fit summaries, and sample-accurate
  LD audio generation. The final x265 encode is video-only; audio is attached by stream-copy remux.
- Added an experimental DVD-free duration/PAD estimator, gated on E07 head-to-head evidence.
- Validation at the original V5 release: 19 tests passed; no E07 DVD-free A/B or full E07 rerun had yet been performed.

Version 6 (2026-11-14)
FROM Version 5 -> Version 6
- Promoted the E07-tested, optional no-DVD LD-audio path for users who explicitly proceed without a
  matching DVD. It records the duration/PAD method and exact audio sample budget; QC clearly reports
  that external absolute A/V cross-correlation is unavailable without a DVD.
- Added a user choice for curated, timestamp-named single-frame cut-PAD stills when no DVD is supplied;
  included verified stills and provenance for the completed E04/E07 cut-PAD cases.
- Added the V5 VapourSynth/macOS helper set and a fresh-Mac setup/profile guide based on M5 field tests.
  A complete V6 final delivery on a fresh Mac remains unvalidated.
- Removed the author-machine FFmpeg path from motion-probe; it now resolves FFmpeg from the machine profile.
- Added a changelog, optional-DVD manifest initialization, and a no-DVD synchronization QC path.
- Validation: see the committed V6 test/compile/PowerShell checks and the E07/M5 device logs; Linux and
  ARM64 platform targets remain research-only unless separately validated.

Version 7 (2026-11-14)
FROM Version 6 -> Version 7
- Added the unified, read-only `scripts/doctor.py` readiness report and platform-specific direct
  Python version locks/bootstrap commands for Windows x86_64, macOS arm64, and candidate Linux x86_64.
- Added an allowlisted, dry-run-first stage runner with doctor/manifest gates and unique per-stage logs.
- Made Qwen runbooks generated from the canonical runbook and short model-policy templates; added
  `generate_runbooks.py --check` to detect drift.
- Added the Linux x86_64 profile/environment candidate. Linux production workflow, a fresh-Mac
  installation, Linux ARM64, and Windows ARM64 remain unvalidated; the tested M5/macOS arm64
  configuration has completed an end-to-end S01E10 workflow.
- Added shared-release mode with unique per-device/instance/episode workspaces under
  `devices/`; manifests and stage logs are routed there, with no-overwrite reference and
  provenance-aware cut-PAD publication. The tooling did not change share ACLs.
- Integrated M5 S01E10's seek-only audio-dropout finding: final QC checks input-seek and
  output-seek five-second audio windows at four timeline points for every master audio
  track. Both remuxers set Matroska `-max_interleave_delta 0`, the verified interleave fix;
  QC failure output documents the repair. Absolute-A/V QC reports use unique names so QC
  can be rerun without a stale-file error. M5 completed an end-to-end macOS arm64 workflow;
  fresh-Mac installation coverage remains separate.
- Fixed shared-mode redaction of JSON-serialized Windows paths in both the stage/doctor
  and ldcommon report paths. JSON-escaped paths are replaced before plain-text paths, with
  a drive-root guard; regression tests cover `D:\` roots and plain-text log redaction.
- Let the allowlisted download stage start after downloader-specific checks without waiting
  for the full toolchain doctor. The downloader still requires a valid profile, curl >=7.71.0,
  verified Archive metadata/MD5 inventory, paired TBC sidecars, and the destination-space gate.
  Complete tool/version, dependency, preflight, and doctor checks during the transfer; do not
  install/update tools until it completes, and do not process before those gates pass.
- Clarified README-relative device workspace placement for any `ld-pipeline` copy, added a
  non-gating `ensure`/automatic resolution path with an isolated local fallback, and added a
  per-workspace logging guide for commands, full output, gates, versions, and provenance.
- Validation: see the V7 entry in the authoring-device log and `V7-RELEASE.md`; installation is
  opt-in and no native tools/plugins are silently installed or upgraded.

Version 8 (2026-11-15)
FROM Version 7 -> Version 8
- Made per-device episode workspaces README-relative for any `ld-pipeline` location, not
  tied to W:. The intended `devices/<device-instance>/episodes/<code>/` folder is created or
  reused automatically; if the README-folder `devices/` path is unavailable, the workflow
  warns and uses isolated device-local profile roots rather than gating the run.
- Clarified ACL policy: the README/source tree is read-only, `devices/` is its only writable
  child, and each device may modify only its own instance subtree. V8 does not modify ACLs.
- Added per-workspace logging guidance and `scripts/stage_clock.py` for manual stages.
  `run_stage.py` logs active elapsed time and gate/action breakdowns; manual clocks can be
  paused during human gate waits so waiting time is excluded from stage duration.
- Fixed the README-workspace local-fallback candidate resolver (a missing device-label
  binding found in the Lenovo Legion device log); added tests for shared-folder creation,
  local fallback, manifest/log routing, and fallback cut-PAD provenance.
- Validation: 63 passed, 7 Mac/VapourSynth-only skipped; Python compilation, PowerShell
  parsing, runbook generation, and timing/fallback tests passed. See `V8-RELEASE.md` and the
  V8 entry in the device execution log.

Version 9 (2026-11-15; application fork prototype only)
FROM Version 8 -> Version 9 (fork-local)
- Added a JSON-plan workflow executor around allowlisted `run_stage.py` actions, with a
  durable state/log, advisory single-job lock, input/output fingerprints, and conservative
  resume rules. Only Archive downloads may be retried automatically after interruption.
- Registered deterministic descriptor, picture-alignment, break-edge, audio-sync, and
  retime helpers; fixed circular PAD-review runner prerequisites.
- Added an intake-plan example and tests for allowlisting, state, changed artifacts, and
  safe download retry. This is not yet a full unattended episode workflow or GUI.
- Split the intake template into explicit read-only instructions and a single editable input
  section, with inline JSON `_comment` explanations. Approval user/time are captured at run
  start instead of requested as inputs.
- Added a fixture-backed, no-network intake integration test covering download interruption,
  resume, initialization, input validation, and verified completed-step skipping.
- Prepared the next stage pair: Orc stack rendering with artifact checks, cross-platform TFM
  log generation, and a macOS cadence adapter. Stack and cadence stages require explicit
  workflow review gates before downstream processing.
- Validation at the initial V9 snapshot: see `V9-RELEASE.md`. A later supervised S01E08
  canary is recorded in the V10 fork-adoption release; no full delivery is claimed.

Version 10 (2026-11-15; mainline safeguards adapted to the application fork)
FROM fork Version 9 -> fork Version 10
- Ported V10 output-silence verification for DVD retiming, including explicit sub-resolution
  LIMIT reporting and QC visibility. Added report-only PAD audio occupancy and LD luma-black
  diagnostics, episode-scoped EFM output planning, alignment-range refusal, break-window
  clipping, legacy workspace compatibility, and one-off analysis safeguards.
- Preserved V9 ordered orchestration, prompt/config intake, review gates, and cadence adapters;
  added the new analysis helpers to the allowlisted stage runner and preflight inventories.
- Added the optional FromStunToKill Tk cockpit prototype over the same saved-plan/CLI
  contract. It derives episode code from the Archive URL/metadata, reuses or creates the
  default per-user profile, derives the manifest/workspace path, provides tooltips, and supports
  Archive URL or local source inventory without requiring `download-manifest.csv`, exact DVD/no-DVD plan generation,
  preview, execution, resume, and explicit human review approval; the CLI remains supported.
- Local intake recognizes common raw-RF extensions as “decode required” rather than passing
  them to the TBC pipeline; raw-RF decoding remains future work.
- Added a navigable PAD-review popup for cut-PAD stills and optional five-image RIFE context
  (source −2, source −1, replacement, source +1, source +2). Only marked app-owned temporary
  preview copies are cleaned up; canonical RIFE outputs and curated stills are preserved.
- Added a bottom-of-window verbose logging checkbox. Standard mode shows diagnostics/progress
  and failure context while retaining full stage output in the workflow log; verbose mode streams
  all child output. CLI output remains verbose by default.
- Interim intake policy: AI-prompted URLs, DVD selections/paths, and settings are acceptable
  inputs, but confirmed values must also be persisted and validated in the designated config
  or plan, not left only in chat.
- Validation: **139 passed, 7 VapourSynth-only skipped**; Python compilation, generated-runbook
  check, whitespace check, warning-as-error import, PowerShell parsing, and stage-list check
  passed. See `V10-RELEASE.md`. The existing S01E08 canary predates this port and does not
  validate new V10 retime/measurement behavior.
